# 模块边界与后续主题方向

## 本次结构调整

基线：v1.2.0 / 9c29af3。App 按 Python AST 起止行计为1350行，本次降至964行（约29%）；不是删注释或压行。新增的是可独立测试的组合对象，不是将同一巨类拆成多重继承或运行时拼接。

| 模块 | 职责与边界 |
| --- | --- |
| quota_monitor.py | 程序入口、当前 provider 适配、App 协调、布局与渲染；仍需后续逐步拆分 |
| widget_settings.py | 套餐/续订/密钥设置，显式注入配置、保存函数和密钥操作；通过 App 触发重绘/可见性 |
| widget_dialogs.py | 只负责输入与提示；不持有网络、调度、凭据读写权限 |
| widget_tray.py | 托盘线程、图标与生命周期；原生回调只入队，不跨线程调用 Tk |
| widget_windows.py | 圆角、重绘、毛玻璃原生调用；不可用时按已有逻辑降级 |
| widget_style.py | 当前颜色/字体等常量；不创建界面，不改变现有主题 |
| app_version.py | 应用版本与 UA 的唯一来源，不混用数据格式版本 |
| monitor_runtime.py / harness_stats.py | 原有调度/进程/安全持久化，以及独立日志统计 |

安装清单 `runtime-files.txt` 由安装器与测试共同使用，新增运行模块必须进入清单。发布包也必须包含该清单全部文件。查询模式和 `--version` 不加载 Tk/PIL/pystray；没有新增轮询、动画或驻留进程。

仍存在的结构债：provider 适配和 App 渲染在主文件里，SettingsController 仍依赖 App 的几个明确回调。本次不把接口全部重写，也不声称已经彻底解耦。下一步可先将 provider 适配拆离入口，再提取无副作用的展示数据模型。

## 主题候选（仅设计计划，未实施）

共同底线：同一份数据和查询流程，主题不能改变金额/额度语义；数字和单位优先，错误/旧数据必须明确。采用静态素材缓存与数据变更重绘，不启用常驻蒸汽/齿轮动画。

- **月之暗面**：石墨黑、月白数字、克制的品牌色。减少每行边框和透明叠字，面向日常常驻。
- **蒸汽算力机**：黄铜边框、黑色仪表盘、额度像压力表；金额仍为数字账本，token 像机械里程表。只做轻拟物，不用复杂动画或背景音。
- **Token 加油站**：额度是油量、余额是燃料预算；品牌像不同加油枪，保留明确名称与单位，不把 token 混成金钱。
- **电子墨水账本**：暖白底、墨黑数字、细线分区，适合长期工作和浅色桌面。

建议先做“月之暗面 + 蒸汽算力机 + 电子墨水账本”三张同尺寸视觉稿，先选方向，再做一款可切换皮肤。最小/常规/大字、透明度和密度应独立于主题。验收包含100%/125%/150%/200%缩放、长套餐名、离线旧数据、透明度与拖动、托盘恢复及闲置占用。该计划不等于已获主题开发授权。
